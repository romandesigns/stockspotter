# Prospective discovery audit, version 1

Primary cohort: the specification's $0.25–$3 quiet-to-running stocks. This definition is frozen before inspecting new outcomes. It is a price-pattern diagnostic, not a buy rule or a profitability test. No old holdout dates are consumed.

An independently observed candidate is the first event per symbol and New York date with a five-minute sampled flat base (maximum/minimum <= 1.02), followed within twenty minutes by a snapshot trade price at least 10% above the base endpoint. The endpoint price must be $0.25–$3. Neither funnel qualification, quiet-watch selection, float nor a scanner alert is required for this label. This keeps the denominator independent of the scanner. Observe 04:00–16:00 ET only; report regular and premarket separately. A sampled base needs an observation within 30 seconds of its beginning and end and no gap over 60 seconds. Each snapshot's underlying trade must be no more than 60 seconds old when received and no more than one second in the future. Repeated old prints cannot fabricate a flat base. Missing forward paths are censored, not counted as negatives. Only fully observed twenty-minute paths enter the base denominator. The first qualifying base per runner is retained; this is an ex-post event label, not the precise breakout onset.

For each candidate report the base endpoint, first observed +10% crossing, actual monitored trade receipt in the 60 seconds before the endpoint, configured monitor presence at the last heartbeat no more than 30 seconds earlier, quiet-watch decision then in force, first confirmed ignition received between the endpoint and crossing, and seconds of alert lead before the crossing. No receipt is **unknown**, not proof of an unsubscribed ticker. Configured monitor presence does not prove provider subscription acknowledgement. The initial report measures observed coverage and alert timing; it does not call these fills, executable opportunities or a whole-market recall rate.

Evidence is collected only when `DISCOVERY_AUDIT_DIR` is set. The regular scanner writes its already-fetched broad snapshot batches with market timestamps, requested universe, completed scan decisions, fifteen-second coverage heartbeats, sampled actual trade receipt and ignition events. There are no additional API calls from recording. Each process has a separate daily file. A 32-record queue isolates disk work from tick dispatch; a per-process daily size cap bounds storage. Queue/disk losses are logged and the cumulative count is attached to later records. A partial last record is an audit gap. These diagnostics may lose their last queued records on abrupt process exit; missing scans/heartbeats and truncated observation windows cannot establish complete recall. Record source-file hashes and capture date/feed in every analysis.

The analyzer rejects unsupported schema or malformed complete lines, reports partial lines, unfinished scans, missing snapshot batches, stale prices, missing snapshot responses and recorded losses. It must return **insufficient evidence** when no candidates are observed, never a fabricated 0%/100% success rate. Even a valid local sample is conditional on this provider's current active, tradable, non-warrant US-equity universe: it includes instruments other than common stock and does not establish historical listing membership or float. Broad snapshots are sequential, not simultaneous; timestamps and observed delays must remain visible.

The one-shot capture utility reads assets/snapshots only and supplies no scanner coverage evidence or float lookups. A closed-market capture validates the recording path but cannot measure discovery. Enable the recorder in the running scanner for market-session evidence. Profitability and quote-based execution analysis follow only after this discovery denominator exists.

Operational settings: the cap is 8 GiB per process per UTC day; the one-shot census measured roughly 2.7 MB for a complete broad snapshot pass. At a fifteen-second interval, raw snapshots alone could approach 4 GB per 6.5-hour session before decision/coverage records. Check disk capacity and retain or archive files deliberately. The recorder is opt-in and does not delete old evidence. The standalone tool drains the queue and synchronizes its file before success; the scanner's tick path never waits for that disk synchronization.

Base labels do not extrapolate before the first observation or beyond the last. Forward paths may cross 09:30 ET; session grouping uses the base endpoint. Anchors overlap and are not independent observations. The one-per-symbol/date event is selected chronologically after labeling, without choosing the strongest move. The reporter retains unknown coverage values and never converts them into a measured miss rate.
